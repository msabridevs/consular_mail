# التغيير المطلوب فقط: فصل الجمهور والموظفين

## النتيجة

- مشروع Vercel للجمهور: الاستعلام فقط، دون زر أو رابط لدخول الموظفين.
- مشروع Vercel مستقل للموظفين: صفحة الدخول عند فتح الرابط مباشرة، ثم واجهات العمل بحسب الصلاحيات.
- الواجهتان تستخدمان نفس قاعدة Supabase ونفس حسابات الموظفين. لا تنشئ قاعدة ثانية ولا تشغل SQL التأسيس مجددًا.
- لا توجد إحالة من موقع الجمهور إلى رابط الموظفين. لا تضف رابط الموظفين في أي متغير أو نص عام.

## نفذ هذه الخطوات فقط

1. من الأرشيف افتح مجلد `UPDATE_ONLY`. ارفع **محتوياته** إلى جذر مستودع GitHub الحالي `consular_mail`، ووافق على استبدال الملفات المطابقة. حافظ على المجلدات: `src` و`api` و`tests` و`docs`. لا ترفع مجلد UPDATE_ONLY نفسه كمجلد إضافي. إذا عرض GitHub نموذج commit، أضف وصفًا ثم اضغط Commit changes.
2. في مشروع Vercel الحالي للجمهور، افتح Settings → Environment Variables وأضف:

   - Key: `VITE_APP_MODE`
   - Value: `public`

   اختر Production ثم احفظ ونفذ Redeploy. المتغيرات الأخرى الحالية تبقى كما هي. واجهة الاستعلام العام تظل تحتاج مفاتيح Turnstile والخادم الموجودة في دليل الإعداد الأصلي؛ فصل الموظفين لا يلغيها.
3. في Vercel اختر Add New → Project واستورد **نفس مستودع GitHub** مرة أخرى. اختر اسم مشروع مستقلًا للموظفين، مثل `consular-office`. اترك Root Directory=`./` وFramework=Vite.
4. في المشروع الجديد أضف **هذه المتغيرات الثلاثة فقط**:

| Key | Value |
|---|---|
| `VITE_APP_MODE` | `staff` |
| `VITE_SUPABASE_URL` | نفس رابط Supabase الذي أدخلته بالمشروع الأول، دون `/rest/v1/` |
| `VITE_SUPABASE_ANON_KEY` | نفس المفتاح العام publishable أو anon الذي أدخلته بالمشروع الأول |

5. اضغط Deploy. افتح الرابط الجديد مباشرة وسجل دخولك. لم تعد تحتاج إضافة `/staff`.
6. أرسل رابط الموظفين لهم عبر وسيلة العمل المعتادة فقط. للجمهور أرسل الرابط الأول.
7. في Supabase → Authentication → URL Configuration، اجعل Site URL رابط موقع الموظفين الجديد. تسجيل الدخول الحالي بالبريد وكلمة المرور وTOTP لا يحتاج إعادة إنشاء الحسابات.

أي تعديل لاحق على نفس المستودع ينشر على المشروعين، وكل مشروع يبني الواجهة المناسبة بحسب VITE_APP_MODE. بعد تغيير أي متغير نفذ Redeploy للمشروع المعني. لا تستبدل قيم المفاتيح الحقيقية بالنصوص الإرشادية في `.env.example`.

## التحقق السريع

- افتح رابط الجمهور: يجب ألا يظهر «دخول الموظفين».
- افتح `/staff` على رابط الجمهور: يعيدك إلى الاستعلام، ولا يعرض تسجيل الدخول.
- افتح رابط الموظفين: يظهر الدخول مباشرة، ثم التحقق بخطوتين.
- طلب `/api/track` على موقع الموظفين يرفض بـ404 ولا يتصل بقاعدة البيانات.
- تحقق أن الموظف ما زال يرى الأقسام المسندة إليه فقط.
- تغيير لغة موقع لا يغيّر لغة الآخر؛ تفضيلات اللغة والجلسات منفصلة بحسب النطاق.

## نطاق الفصل

الفصل يتم وقت البناء، وليس إخفاء زر فقط. الموقع العام لا يبني كود تسجيل دخول الموظفين ولا مكتبة Supabase الخاصة بتعاملات المتصفح. الموقع الداخلي يبني أدوات الموظفين فقط. ملفات المصدر تبقى في مستودع GitHub الخاص.

الرابط المنفصل يقلل ظهور واجهة الموظفين للجمهور، لكنه لا يضمن عدم اكتشاف الرابط. من يعرف رابط الموظفين يمكنه رؤية شاشة الدخول، وتظل البيانات محمية بكلمة المرور والعامل الثاني وصلاحيات قاعدة البيانات. إذا أردت منع فتح الشاشة نفسها إلا من شبكة البعثة، تحتاج طبقة تقييد وصول إضافية؛ هذا التعديل لا يفرض VPN أو شبكة خاصة.

## الملفات التي تغير التنفيذ

`src/main.jsx`, `src/shared.jsx`, `src/shell.jsx`, `src/public.jsx`, `src/staff.jsx`, `src/staff-main.jsx`, `vite.config.js`, `vercel.json`, `api/track.js`.

يتضمن UPDATE_ONLY أيضًا `.env.example` للتوثيق، وهذا الدليل، واختبارات الفصل. لا تغيير في package.json أو package-lock.json أو SQL أو بيانات Supabase.
