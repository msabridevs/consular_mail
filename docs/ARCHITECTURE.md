# Design and official references

## Data path

Public browser → POST /api/track on Vercel → persistent HMAC-IP rate limit → Turnstile server validation (including hostname and action) → service-only lookup_public RPC → explicitly allowlisted result.

Staff browser → Supabase Auth password + TOTP → authenticated RPC → private.actor() checks active staff and aal2 → department and role checks → private tables. No service key in the browser. Session tokens use sessionStorage rather than permanent localStorage. Language preference alone uses localStorage.

Public requests use POST, not query strings, and responses use no-store. Application code does not log tracking numbers, names, tokens, passwords or internal notes. Platform access logs and Cloudflare processing are subject to those platforms' configuration. The staff creation CLI deliberately prints a generated temporary password once to a trusted local terminal.

## Tables

| Table | Purpose |
|---|---|
| private.staff | Auth UUID, display name, role, department array, active flag |
| private.mail | Incoming tracking number, sender, EUR cents, section, status, timestamps, bilingual public notes, internal note, return tracking, version |
| private.events | Actor UUID/name, action/time, old and new snapshots; application accounts cannot modify events |
| private.rate_limits | HMAC of client IP, 10-minute window, counter; old buckets deleted on subsequent requests after 24 hours |

Auth users, hashed passwords and MFA records are maintained by Supabase Auth. There is no duplicate publicly readable tracking table. The public projection deliberately returns ONLY tracking, registered_date, status, note_ar and note_de. The database necessarily stores additional internal fields to support the requested workflow.

## Integrity

Registration timestamp is generated by PostgreSQL. Monetary input is parsed to integer cents without binary floating-point rounding. The SQL constraint requires nonnegative EUR cents. Tracking numbers are unique. Mutations use narrow functions rather than arbitrary update payloads. Batch rows are locked in UUID order. Client passes row versions; stale writes fail and the whole transaction rolls back. All insert/update operations write audit snapshots in the same transaction.

Status graph: registered → processing → returned; processing → waiting → processing. No direct registered → returned. Admin corrections are audited; changing department after receipt is forbidden. All table access from client roles is revoked. RLS is enabled with no client policies. SECURITY DEFINER helpers pin search_path to the empty string and qualify schema names. The only anonymous data path is the Vercel server route; anon cannot execute public lookup directly.

## Operational assumptions

Vercel is the direct trusted edge for the API. If deploying behind another proxy or changing to another provider, revisit IP extraction before relying on rate limiting. The rate limit (20 requests / 10 min / IP) is intentionally basic; it is not DDoS protection or proof of identity. Rate-limit storage operations fail closed. Turnstile validation fails closed. A determined person who knows a number can see the intentionally public result.

Dates in dashboard use Europe/Berlin. The overdue threshold is 7 calendar days from registration. Dashboard aggregates are calculated by PostgreSQL across all authorized records; the table is independently filtered and paged by 50. On-demand history includes every event for one record.
